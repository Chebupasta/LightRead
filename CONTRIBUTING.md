# Участие в разработке LightRead

Спасибо за интерес к проекту. Ниже — правила, которые помогают сохранить читалку стабильной.

## Окружение

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Минимально поддерживаемая версия Python — 3.10. Основная зависимость — PySide6; новые «тяжёлые» зависимости не добавляются без обсуждения.

## Перед pull request

1. Прогоните полный набор тестов: `python -m unittest discover -s tests -v`.
2. Добавьте тест на новую логику, если это возможно без тяжёлых зависимостей.
3. Проверьте, что не сломаны публичные API: методы, сигналы, слоты и ключи настроек.
4. Для визуальных изменений проверьте обе темы и оба режима библиотеки (сетка/список).

## Архитектурные ограничения

- `common.py` — источник правды по темам и токенам. Уровни: primitive → semantic → chrome.
- `theming.py` только применяет токены к QSS/QPalette.
- `ui.py` рисует карточки через semantic-токены и сохраняет кэши `BookDelegate`.
- В `THEMES` ровно две темы; `bg`/`fg` остаются чистыми `#ffffff` / `#000000` — на это опираются тесты и текст страницы.
- Не удаляйте и не переименовывайте публичные методы, сигналы и ключи настроек без обратной совместимости.
- Не добавляйте тяжёлые зависимости: работаем на PySide6 + стандартной библиотеке.

## Стиль кода

- Читаемый и последовательный код без закомментированного старого кода.
- Предпочитайте простые решения.
- Коммиты — небольшие и тематические, с понятным сообщением.

## Сообщение об ошибке

Используйте шаблон issue из `.github/ISSUE_TEMPLATE`. Пожалуйста, указывайте версию Python/PySide6, ОС, формат книги и минимальный пример воспроизведения.
